# 验收测试

## 无破坏验证

1. 构建并打开应用，确认显示「观察模式」，没有自动终止 Claude。
2. 在「出口与规则」检查目标地区（默认 JP）。观察当前 IP 和地区；不要将示例地址当成真实出口。
3. 在「保护测试」依次运行四种模拟。预期网络超时不急停但启动被阻止；其他三种异常进入模拟锁定。网络恢复后保持锁定，手动恢复才解锁。
4. 查看「事件记录」，确认能看到本机状态与出口检测结果，日志中没有账号凭据。
5. 用 `swift test --disable-sandbox` 执行自动测试；用 `swift run guardian-diagnostics --network` 只读检查真实环境。

## 需要用户操作的真实验证

先保存所有 Claude 工作。测试选中的保护对象都会受到影响。

| 操作 | 预期 |
| --- | --- |
| 正确配置后启用保护，从本应用启动 Claude | 新检查通过才启动 |
| 在测试页确认真实急停 | Claude 退出，状态锁定 |
| 锁定时从 Finder 或原始 CLI 启动 | 下一次本机巡检发现后终止，存在检测窗口 |
| 只恢复网络但不点击恢复 | 保持锁定 |
| 检查通过后点击手动恢复 | 解锁，不自动重新启动 Claude |
| 运行期间设置错误的指定公网 IP 并保存 | 检测出不匹配后急停并锁定 |
| 修正指定 IP 并保存 | 仍保持锁定，直到手动恢复 |
| 保护运行期间主动关闭 Clash Party 内核或 TUN | 本机检查确认后急停并锁定 |
| 保留内核和 TUN，只令网络探针超时 | 显示未知，不急停，新的受管启动和解锁被阻止 |
| 关闭主窗口 | 菜单栏保留，监控继续 |
| 退出应用再打开 | 默认观察模式；锁定仍保留，需重新启用保护 |

网络超时模拟和真实网络故障是不同验证。Wi-Fi 关闭可能同时改变路由或导致代理主动关闭 TUN；若观测到明确的内核/TUN 异常，按硬故障急停，不等同于纯网络超时。

## 尚未覆盖的环境

- 非标准 Claude CLI 安装路径、Node 复杂启动参数、App Translocation 或修改名称的应用。
- 完整 IPv6、DNS、WebRTC、按域名/进程分流，以及守护程序自身被强制结束。
- 当前用户以外的进程、系统级防火墙阻断、开机无人值守运行。
